# FIX4 实车测试清单

本次仅做了 GCC 原生仿真；ARMCC 5 编译和实车测试均未验证。请先在你的本机用
Keil ARMCC 5 重新编译本工程，确认编译、链接成功后再烧录。不要把仿真通过
当作已经通过 Keil 编译或实车验证。

## 先按默认参数跑 15 次

1. 烧录后在空地上做直线起步 5 次。每次从静止开始，记录左右轮是否都起转、
   起转是否明显先后不一、车头是否偏向一侧，以及是否停车。
2. 左转直角跑 5 次。记录推进时是否偏航、首次扫描方向、是否转过线又反向、
   是否重新进入循迹，以及是否停车。
3. 右转直角跑 5 次，记录同样的信息。右转结果单独记录，不能用左转成功代替。
4. 任何一次停车，先拍下 OLED 第一行的完整文字与 `D:nn`，再重启。
   编码器故障显示 `ENC STOP D:nn`；丢线停车显示 `LOST STOP D:nn`。
   `Track_Start()` 会清除上一次 D 码，重启前务必记录。
5. 同时记录电池电压、地面材质、线宽、车上负载和所用固件版本。录像最好能
   同时看到车头、两轮和轨迹，便于区分起步卡住、推进偏航与扫线漏读。

可按下面的格式填写，每次测试占一行：

| 日期 / 固件 | 项目 / 次数 | 电压 / 地面 / 负载 | 左右起转情况 | 推进偏航 / 首扫方向 | 是否恢复循迹 | OLED 第一行 / D码 | 本次唯一改动 |
|---|---|---|---|---|---|---|---|
| | 直线 / 1～5 | | | | | | 默认值 |
| | 左直角 / 1～5 | | | | | | 默认值 |
| | 右直角 / 1～5 | | | | | | 默认值 |

## D 码对应的排查顺序

先查机械、接线、编码器和探头，再根据证据调参数。下面的参数建议用于定位，
不代表提高某个数值一定能修复故障。每次只改一个参数；重新编译、烧录并重复
相同测试，把旧值、新值和实际结果记下来。

| D码 | 含义 | 优先排查 | 参数建议 |
|---|---|---|---|
| 01 | 左轮无脉冲 | 左轮是否卡住；电机是否实际转动；电源、驱动与左编码器接线是否正常。已助推到封顶仍无脉冲才会报此码。 | 若轮子实际转但计数不变，先修编码器，不增加 PWM。若确实起不来，先测落地起转 PWM，再评估 `TRACK_KICK_MAX_PWM`；若起转太慢，可单独评估 `TRACK_KICK_STEP_PWM`。 |
| 02 | 右轮无脉冲 | 同上，针对右轮；特别记录左右起转门槛差异。 | 同 D01，不能用增加 PWM 掩盖卡轮或编码器无脉冲。 |
| 03 | 左轮反向 | 先查电机/编码器接线、左右通道和编码器符号；确认物理前进时计数方向与 FIX4 基线一致。 | 不先调速度参数，不盲目改方向宏。方向宏保持本任务基线值；接线应与基线匹配。 |
| 04 | 右轮反向 | 同上，针对右轮。 | 同 D03。 |
| 05 | 直角推进超时 | 是否推进卡住、编码器距离是否有效、左右轮是否同时走、车头是否持续偏向一侧。 | 确认起转正常后，若推进明显偏航，可单独调整 `TRACK_APPROACH_YAW_KP`；补偿频繁到上限时再评估 `TRACK_APPROACH_YAW_MAX_RPM`。不要先延长推进超时。 |
| 06 | 直角旋转超时 | 两轮是否都按方向旋转、是否反复停转、探头是否确实扫到线；拍下推进偏航和扫线过程。 | 转不起来先按 D01/02 排查助推。看见线却确认不了时，先检查探头/线宽，再单独评估 `CORNER_ALIGN_RPM` 或 `CORNER_CENTER_SAMPLES`；不要先延长旋转超时。 |
| 07 | 直角两侧都扫完没找到线 | 线是否进入探头范围、是否已转过线、推进是否偏航、探头是否漏读；全黑横带没有左右线索时，首次扫描方向可能使用上次方向或默认左侧。 | 推进偏航看 `TRACK_APPROACH_YAW_KP`；扫过中心太快可评估 `CORNER_ALIGN_RPM`。`CORNER_CENTER_SAMPLES=2` 已允许一帧间隙，降低样本数会增加误认风险，须记录对照结果；不要先改 55° 门槛或扩大扫描范围。 |
| 08 | 普通搜索超时 | 丢线起点、搜索是否实际旋转、探头是否漏读、线是否仍在可搜索范围。 | 起转问题看助推参数；确认问题看 `CORNER_ALIGN_RPM` / `CORNER_CENTER_SAMPLES`。不要先延长 `TRACK_SEARCH_MAX_MS`。 |
| 09 | 普通搜索两侧都扫完没找到线 | 是否已偏离线路、线是否出现在边缘却没进入中心、探头是否稳定；记录最初丢线位置。 | 确认问题同 D08；只在有录像和探头证据后评估搜索速度 `TRACK_SEARCH_RPM`，不要把扩大搜索角度当作默认修复。 |
| 10 | 贴边对线超过 35° | 探头是否持续贴最外侧、内外轮动作是否正确、线的曲率和位置是否适合本次对线。 | 先查起转与探头，再评估 `TRACK_EDGE_PIVOT_RPM` / `CORNER_ALIGN_RPM`。保留 35° 限制，不直接扩大角度掩盖失败。 |
| 11 | 贴边对线超时 | 外轮是否起不来、是否一直贴边不回中心、探头或线面是否有漏读。 | 起转问题看助推参数；轮子正常但无法居中时评估 `TRACK_EDGE_PIVOT_RPM` / `CORNER_ALIGN_RPM` / `CORNER_CENTER_SAMPLES`。不要先延长对线超时。 |

`CORNER_CENTER_SAMPLES` 同时影响扫线与贴边对线，调整后必须重跑左右直角和
正常绕圈。提高样本数会使窄线更难确认；降低样本数会使单帧噪声更容易被接受。
起转或扫线改善后，也要观察正常循迹是否新增摆动、冲过线或停车。

## 当前关键参数

参数位于 `hardware/CarConfig.h`，先保留以下默认值测试：

| 参数 | 默认值 | 含义 / 单位 |
|---|---:|---|
| `TRACK_STALL_KICK_MS` | 60 | 原始轮速在 (-6, 6) RPM 内持续多久开始助推，ms |
| `TRACK_BOOST_PWM` | 18.0 | 助推起始 PWM 下限，% |
| `TRACK_KICK_STEP_PWM` | 2.0 | 每个控制周期增加的 PWM 百分点；正常周期 20 ms |
| `TRACK_KICK_MAX_PWM` | 40.0 | 助推 PWM 封顶，% |
| `TRACK_APPROACH_YAW_KP` | 40.0 | 推进偏航的单轮目标补偿系数，RPM/rad |
| `TRACK_APPROACH_YAW_MAX_RPM` | 10.0 | 推进偏航单轮补偿上限，RPM |
| `CORNER_APPROACH_RPM` | 50.0 | 直角推进基准目标速度，RPM |
| `CORNER_RPM` | 42.0 | 直角扫描目标速度，RPM |
| `CORNER_ALIGN_RPM` | 30.0 | 扫到中心附近后的慢速对线目标，RPM |
| `CORNER_CENTER_SAMPLES` | 2 | 扫线确认帧数；首帧严格居中，后续近中心，允许一帧间隙 |
| `TRACK_MAX_PWM` | 30 | 正常速度环 PWM 上限，%，本任务不改 |
| `FORWARD_PWM` | 30 | KEY5 手动直行固定 PWM，%，本任务不改 |

不要把助推得到的 PWM 预灌进速度环积分。读到原始轮速 ≥8 RPM 后助推会清零，
速度环接管；以后再次停转仍可重新助推。

## 做一次左右轮落地起转实测

车轮着地，使用与正常行驶接近的电池、地面和负载，把 PWM 从 0 缓慢上升，
分别记录左轮、右轮开始持续转动的 PWM。可以每次增加 1～2 个百分点并观察，
一旦开始转动就记录并结束本轮，避免把滚动后的维持 PWM 当成静止起转门槛。
至少重复几次；每次让轮子完全停下再开始。记录电压和地面条件。

现工程没有 PWM sweep / 递增测试工具。这一步需要你使用临时测试程序或可调
PWM 工具；本次交付没有提供该工具。测试应留足车辆移动空间，并能立即停止。
KEY5 始终固定 30% 手动直行，只能检查这个固定点的表现，不能代替从 0 缓慢
上升的起转测量，也不能测出左右轮各自的门槛。

把测出的左右起转 PWM 与停车 D 码一起反馈，再决定是否调整助推封顶或步长。
不要只因为仿真使用了 20%、24%、26% 就把它们当作实车门槛；仿真中的起转
门槛、左右不对称和响应时间都只是模型假设。

轮径 / 轮距 / 前置距 44 / 133 / 175 mm、每圈计数 251.0 / 265.35、编码器和
电机方向宏、正常 `TRACK_MAX_PWM=30`、KEY5 固定 30% 保持原值。
