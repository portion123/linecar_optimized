# FIX4 P1～P5 修复与验证报告

本次以用户 ZIP 中的 FIX4 为基线，完成 P1～P5 局部修复。故障矩阵 **84/84**、扩展随机 **60/60**、原有回归 **53/53**、必需几何 **34/34**，新增行为检查 **15/15**。必需几何 RUN 最大前探头误差从 **28.66 mm 降至 25.74 mm**。

**ARMCC 5 / Keil 编译：未验证。实车：未验证。** 本次执行的是 GCC 原生硬件替身中的真实 C 控制代码。

可选压力场景 **8/10**，两项圆弯仍超过原有 25 mm 边界，不能报告为全部通过或已解决高摩擦跟线精度问题。P6 未实现。

## 文件与函数改动

生产代码仅修改 `hardware/Track.c` 与 `hardware/CarConfig.h`。`Track.c` 为 **639 → 665 行**，未增加状态机阶段，未使用 `linecar_optimized` / `FIX4_MINFIX` 作为基线。

| 文件 / 函数 | 改动与原因 |
|---|---|
| `Track.c / SpeedOutput` | 每轮独立 `kick_pwm`。目标达到最低驱动转速，按目标方向换算的原始转速持续在 (-6,6) RPM 内 60 ms 后，从 18% 下限逐帧加 2 个百分点，封顶 40%；读到 ≥8 RPM 立即撤回，可重复助推。PID 上限取 max(30,助推下限)，避免 upper<lower 返回旧输出。没有把助推 PWM 预灌到积分。 |
| `Track.c / ResetPID` | 清除助推幅值及停转计时；删除一次性锁存、助推时长与重新武装计时。保留原有运动负载补偿逻辑。 |
| `Track.c / EncoderFault` | 保留原有目标/PWM门槛、700 ms 无脉冲及 250 ms 反向判据。无脉冲停车增加“已助推封顶”门控，返回左/右轮子原因；反向判据独立生效。700 ms 从原有有效检测帧累计，不是封顶后另等700 ms。 |
| `Track.c / BeginApproach、Control(APPROACH)` | 进入推进时清零偏航；每帧累计 (右轮距离−左轮距离)/轮距。目标为 50±hold RPM，hold=clamp(40×偏航,−10,10)。正偏航表示左偏，因此左轮加速、右轮减速。 |
| `Track.c / BeginScan` | 直角扫描保留推进偏航，55°识别门槛与105°上限均相对推进起始的原直线方向；普通 SEARCH 仍清零。清确认数与漏读间隔。 |
| `Track.c / NearCenter、Scan` | 新增窄线近中心判据：非零、宽度≤正常线宽+1、连续、不含最外侧0x81、误差绝对值≤3。首帧仍须严格 Centered；后续可容一帧缺失，缺失帧不增加确认数，后续须再次见线。两帧连续缺失重置。换向时清确认与间隔。 |
| `Track.c / Track_Stop、BeginEdgeAlign、Control(调度空档)` | 清 `center_gap`，避免不同扫描/控制片段串联确认。贴边对线原有确认逻辑保持。 |
| `Track.c / Halt、Track_Start、Control、Scan` | `Halt(reason,detail)` 先撤去PWM和控制状态再保存诊断；启动循迹清诊断；各故障路径记录D01～D11。 |
| `Track.c / Display` | 第一行显示 `ENC STOP D:01` / `LOST STOP D:07` 等无符号两位数字。直接调用已有 ShowChar，避免参考补丁 SignedNum 产生 `D:+01`。 |
| `CarConfig.h` | 新增5个参数，删除4个弃用参数，更新助推与确认语义注释。原有宏值保持。 |
| `tests/test_calibration.py` | 仅修改获准的 test_04 与 test_09，理由见下文。 |
| `tests/test_fault_matrix.py` | 从用户5页PDF恢复测试源码；7负载、循环顺序、随机种子、通过条件及最终断言均保留。 |
| `tests/test_fault_random.py` | 增加60例方形双向随机：L2、BA20/26、BA26/20、BA24、heavyR × 4%/8%漏读 × 种子11～13。复用附件矩阵的模型与通过条件。 |
| `tests/test_fault_details.py` | 新增15项真实控制路径检查：D01～D11、真故障PWM清零、两位OLED/不越界、KEY5、重复助推/撤回、不预灌积分、推进反馈符号/上限、角度基准、扫线首帧/漏读/换向清理。 |
| 文档 | 新增本报告、实车测试清单、PDF提取说明；在原FIX4说明顶部标明它是历史基线说明。 |
| 生成证据 | 更新几何结果、轨迹、压力结果，新增随机结果；`validation/` 保存基线、每个累计修改阶段和最终执行的日志及JSON汇总。 |

`system/PID.c`、`tests/native/harness.c`、`tests/native_api.py` 和几何模型未改。检查了 harness 与全部 Python 测试，没有废弃助推变量/宏引用。

以下值保持：轮径/轮距/前置距 **44/133/175 mm**、左右每圈 **251.0/265.35**、探头/编码器/电机方向宏、闭环 `TRACK_MAX_PWM=30`、KEY5固定30%、位置与速度PI增益、原有全部几何通过边界。

## 新增与变更参数

PWM 的单位为百分比；“每帧+2”表示增加2个百分点。

| 参数 | 默认值 | 单位 | 含义 |
|---|---:|---|---|
| `TRACK_STALL_KICK_MS`（新增） | 60 | ms | 原始轮速持续位于(-6,6)时的助推等待时间 |
| `TRACK_KICK_STEP_PWM`（新增） | 2.0 | PWM百分点/控制周期 | 未转动时助推下限递增量；默认周期20 ms |
| `TRACK_KICK_MAX_PWM`（新增） | 40.0 | % PWM | 临时起转下限封顶，封顶仍无脉冲才允许无脉冲故障停车 |
| `TRACK_APPROACH_YAW_KP`（新增） | 40.0 | RPM/rad | 每轮推进航向补偿增益；左右目标总差为2×hold |
| `TRACK_APPROACH_YAW_MAX_RPM`（新增） | 10.0 | RPM | 每轮推进航向补偿绝对值上限 |
| `TRACK_BOOST_PWM`（语义变更，数值不变） | 18.0 | % PWM | 反馈式助推起始下限 |
| `CORNER_CENTER_SAMPLES`（语义变更，数值不变） | 2 | 有效确认帧 | 首帧严格居中、后续近中心，期间允许一帧漏读 |

删除 `TRACK_BOOST_WAIT_MS`（旧120 ms）、`TRACK_BOOST_DURATION_MS`（旧40 ms）、`TRACK_BOOST_REARM_MS`（旧100 ms）、`TRACK_BOOST_EXTRA_PWM`（旧4百分点）。同时删除 `boost_used`、`boost_left_ms` 和不再使用的 `moving_ms`。

停转(-6,6) RPM、撤回8 RPM、近中心误差3和单帧间隔沿用任务给出的固定条件，未扩展成更多调参入口。

## 压力场景逐项结果与处理判断

下表误差为RUN阶段前探头最大误差；圆弯的全阶段最大误差与此相同。+1为方形逆时针左转，−1为顺时针右转；圆也使用相应方向。

| 场景 | FIX4 | 最终 | 原误差→最终误差(mm) |
|---|---|---|---:|
| circle +1 R200 | PASS | PASS | 14.10 → 14.05 |
| circle +1 R250 | PASS | PASS | 14.42 → 14.62 |
| circle +1 R300 | FAIL | **FAIL** | 30.01 → **31.26** |
| circle +1 R350 | PASS | PASS | 15.85 → 16.28 |
| square +1 | PASS | PASS | 25.21 → 26.97 |
| circle −1 R200 | PASS | PASS | 14.11 → 14.14 |
| circle −1 R250 | PASS | PASS | 14.70 → 14.62 |
| circle −1 R300 | FAIL | PASS | 25.62 → 24.34 |
| circle −1 R350 | FAIL | **FAIL** | 27.92 → **25.15** |
| square −1 | FAIL（LOST，0.248圈） | PASS（1.177圈） | 16.75 → 28.76 |

最终10项均结束于RUN且无ENC/LOST；两项失败是圆弯超出原有25 mm边界，完成绕圈不能替代精度通过。square −1 的旧最大误差取自停车前的短轨迹，与完成整圈后的误差不能直接视为精度改善/恶化。

压力通过项从6增至8，既有通过项没有变成失败，但不是所有压力误差都下降：+1 R300 从30.01增至31.26 mm。此局限与参考补丁一致，极端高摩擦圆弯精度没有整体改善。`--stress` 的退出码为0仅说明34项必需几何通过，脚本原本不对可选压力统一断言；报告仍单列两项FAIL。

本轮不继续修改位置环、恢复策略或实现P6。所需门槛已满足，而继续按未实测的摩擦模型调参会扩大任务并可能损害正常绕圈。两项压力失败保留为后续问题：先测落地起转门槛和左右实际响应，再据实测负载检查紧圆弯跟线误差。如果实车在对应圆弯持续贴边或D10/D11停车，需要进一步处理；本轮不将它宣称为已修复。

## 仿真验证范围与未验证项

验证了真实 `Track.c` 经 `ReadLine → FollowLine / Scan → DriveTargets → SpeedOutput → PID_Step → SetPWM` 的逻辑，在指定独立电机/几何模型中可以起步并完成84矩阵与60随机；700 ms且助推封顶仍无脉冲以及反向会停车；D01～D11控制路径/OLED格式、KEY5、确认容错、角度基准及原回归均有执行证据。

没有验证真实电机低速曲线、落地起转门槛、左右不对称负载、响应时间、打滑、探头实际间距/漏读分布、电池电压变化、真实中断/OLED耗时或调度。这些动力学、摩擦与逐探头独立随机漏读均为模型假设；已确认的尺寸/计数不能让这些假设自动变成测量。

**未进行 ARMCC 5 编译、Keil完整链接或生成本次可烧录HEX；未进行实车测试。** 源码与Keil C99配置经过只读审查，但不能代替编译。15项构造反馈检查也不是实车故障注入。修复包排除原ZIP中的旧HEX/AXF、旧编译日志与旧哈希清单，避免把FIX4基线固件当成本次输出。
