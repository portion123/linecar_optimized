# STM32F103ZE 循迹、直角转弯与失线恢复优化报告

已在原 FIX4 工程上修改源码，保留主循环、探头分块读线、位置 PD、左右速度 PI 和底层驱动 API。新流程加入角点置信确认、分段慢转、ALIGN、稳定 EXIT，以及不能被假恢复刷新的 Recovery Session。

**当前验证结果：94项单元通过；34项标准几何通过；10项高摩擦压力通过9项、失败1项，失败后有限修正并停车。没有完成本次修改的 STM32 ARM 编译、烧录或实车验证。** 原包里的 HEX/AXF 已移到 `docs/original_evidence/firmware`，不可当作本次修改的固件。

## 1. 原问题分析及 A～I 核实

完整原调用关系与修改前证据见 [阶段0扫描](阶段0_扫描与核实.md)。关键关系如下：

```text
main → KEY_Scan / Track_HandleKey
     → Track_Task（主循环，20ms）
         → Control → Encoder_GetPair → RPM/mm/yaw
                    → ReadLine / ResolveSide
                    → 状态机 / FollowLine（位置PD→左右目标RPM）
                    → DriveTargets（目标斜率）
                    → SpeedOutput ×2（速度PI→带符号PWM）
                    → Motor_Set*speed → TIM2 PWM
         → Display（显存）/ OLED_Service（空闲分片）
TIM3 ISR → 毫秒计时；编码器 EXTI ISR → 条件下降沿计数
```

## 3. 新转弯流程与条件

```text
                 稳定原线100ms且前进8mm / 候选衰减
               +------------------------------------+
               |                                    v
TRACK --> CORNER_CONFIRM --> CORNER_APPROACH --> TURN_FAST
             |                   |                  |
       宽度/中心/触边计分     按编码器推进轮轴       0~50°:42RPM
       置信>=4且>=40ms      目标130~190mm          |
       随后全白>=40ms       硬上限200mm           v
                                               TURN_SLOW
                                               50~70°:30RPM
                                               >=70°:18RPM
                                                   |
                                  >=70° + 中心窄线 + |E|<=2
                                  趋势/跨中心方向合格 + 连续6帧
                                                   v
                  TRACK <-- EXIT <-------------- ALIGN
                            28→40→60RPM           基础24RPM
                            时间+线稳定升档        误差差速±10RPM
                            >=700ms               中心连续160ms
                            稳定400ms+前进25mm

阶段超时/距离/角度/故障/会话预算 --> STOP（锁定PWM=0）
TURN达到105°未接线 --> 出线附近反向最多15° --> ALIGN 或 STOP
ALIGN/EXIT白线<120ms --> 原转向预期方向附近低速前进修正
白线>=120ms --> 同一会话的附近15° SEARCH --> ALIGN 或 STOP
```

**CONFIRM** 综合黑数、连续黑区宽度、中心/边缘位置及近期方向；强形态加2、弱形态加1，不成立衰减或短时保留。单侧方向另有两票门槛。没有把单帧4/5/6路直接等价为某种动作。候选最多1800ms/100mm。

**APPROACH** 沿用 `175−测得宽带半宽−离带后已走距离+trim`，目标夹限130～190mm。起始用28RPM同步左右速度100ms后推进50RPM，距离目标35mm内降到28；左右目标差最多12RPM，并用累计偏航补偿。超200mm、15°偏航或6s即停。转向几何与编码器标定未改。

**TURN / ALIGN** 使用编码器净转角控制42→30→18RPM；每次请求变化仍经斜率限制。扫到中心不直接交回高速循迹；只有符合角度、窄线、中心、误差、趋势且六帧连续，才切换低速差速前进。ALIGN内轮最慢14RPM，连续前进；中心160ms后才进EXIT，最大1800ms/65mm/附加20°。

**EXIT** 28RPM起步；至少200ms且合格线80ms才允许40RPM，至少500ms且合格线200ms才允许基础60RPM；满足700ms、合格线400ms和25mm后交回TRACK。实际左右速度环目标每周期加速最多2RPM；短白线不立刻反向旋转。普通弧弯恢复的EXIT允许稳定偏侧窄线，直角EXIT仍要求中心区域，以免把紧弧弯误当成必须正中直线。

### 方向与普通失线

可靠当前角点方向 → 600ms内hint → 2000ms内已确认转向历史 → 300ms内弱偏差。弱方向只允许两侧12°试探；完全对称且无任何方向信息时，没有可由代码可靠决定的首向，采用中性预测/减速观察，300ms后停车。此处理优先满足不失控和左右对称；不会凭固定默认值扫100°以上。

普通失线保留最近差速最多80ms，之后先15°、24RPM小搜索，再36RPM扩大到60°，最多一次反向到另一侧60°。持续最外探头看到线的情况使用明确pivot：内轮0、外轮50RPM，不把有线弧弯直接变为反向旋转。

### Recovery Session

会话保守地从**首次白帧**开始，持续贴边接管也建立会话。BeginScan只重置当前局部扫描，不重置会话起点、累计绝对转角、尝试或绝对轮行程（现 Track.c:611、:654）。

任一项达到即停：12s、4次尝试用尽、累计绝对转角300°、两轮绝对轮行程平均700mm。TRACK/CONFIRM/APPROACH/TURN/ALIGN/EXIT/SEARCH都受同一预算约束。短暂“看到中心→又全白”不会补预算；交替短白帧超过2s也升级搜索。

只有正常TRACK内连续合格窄线、正向移动**同时满足600ms与30mm**才清会话；不能静止摆在线上刷新预算。正常紧弧弯可用稳定侧线清会话，直角接线本身仍要更严的ALIGN/EXIT。异常停机保留现场，需按键重新启动。

## 4. 左右、正反对称性依据

- **探头误差镜像**：`2*first+n−1−7`（现 Track.c:115）；镜像位序后误差变号。相同距离的对称分离块不再选先扫描的左块，而是标含糊、等速低速并限时停止（:120、:860）。
- **位置目标镜像**：左右目标为 `base+correction / base−correction`（:589）；负偏差降低左轮、提高右轮，正偏差相反。ALIGN也用同一镜像形式（:795）。
- **角点方向镜像**：左触边只给−1票，右触边只给+1票，门槛相同（:500、:530）；SelectDirection没有默认左（:592）。当前可靠角点覆盖旧hint/历史，右hint不会被默认左抢先。
- **旋转符号一致**：`left=dir*rpm, right=−dir*rpm`（:732）。dir=−1时左反右正，左转；dir=+1相反。`yaw=(right_mm−left_mm)/133` 左为正，`progress=−dir*angle` 两个方向都向正增长（:949、:718）。
- **编码器左右标定分别使用**：物理左251、右265.35计算各自RPM/mm，没有用同一count假装同一位移（:943）。完整角点镜像测试按各轮标定量化，状态序列一致、转角差≤0.012rad。
- **正反速度路径相同**：先取速度大小、投影反馈、统一PI/限幅/助推，再恢复方向符号（:314、:331、:397）。负目标同样不被低速停轮；方向补偿缓存为`[wheel][direction]`，正反各自学习，换向清I/D后只继承对应方向（:324）。
- **换向故障对称**：脉冲先乘命令方向，再统一判断反向净计数和占比；零count不清历史，新方向PWM实际施加才消耗260ms宽容（:399）。

**已测试**：软件镜像、稀疏反向反馈和正反输出路径。**需实车验证**：MOTOR_SIGN/ENCODER_SIGN与实际接线、四种正反低速摩擦、轮胎打滑；软件对称不保证左右轮在未测负载下的实际响应完全相同。四个符号宏保持原值。

| TRACK_RECOVERY_MAX_MS | 12000ms | 8000～15000ms | 允许更长恢复，晚停车 | 早停车，复杂恢复可能没走完 | 最高：有限时间 |
| TRACK_RECOVERY_MAX_ATTEMPTS | 4 | 3～5 | 多给局部修正，假恢复可持续更久 | 更快停止反复尝试 | 最高：禁止转圈 |
| TRACK_RECOVERY_MAX_ANGLE_RAD | 300°累计绝对角 | 220～360° | 更大搜索预算，活动范围增加 | 更早保护停车 | 最高：活动范围 |
| ENCODER_REVERSAL_GRACE_MS | 260ms | 200～400ms | 容纳惯性更久，错误方向更晚发现 | 故障发现早，换向可能误报 | 高：先核对方向 |

其余关键保护保持：会话路程700mm（建议500～900）、推进硬上限200mm（190～215）、CONFIRM1800ms、ALIGN1800ms、EXIT3000ms。先查停止原因和目标/实速差，再判断是否需要调；不要首先放大搜索预算。

低速摩擦不在本次虚构为实测值。正向偏置仍为左6.478873%、右4.672686%，反向初值分别相同；正反前馈同样沿用对应原值。A阶段如发现一轮某方向持续起不来，先确认方向/机械阻力，随后对该轮该方向的 `*_DRIVE_OFFSET_PWM` 做约0.5%小步调整并观察PI/PWM，通常先在原值±2%内试。助推仍18/22%、持续40ms，另有最多120ms爬升；不得拿长期高PWM掩盖编码器故障。

## 7. 实车验证 A→F

OLED第一行显示状态、`H` hint和`D`当前转向（−1左、+1右）；停止显示 `R` 原因。第二行 `IR` 八位黑线和 `E`当前探头偏差。第三行轮换 `T`斜坡后目标RPM、`P`PWM、`A`带符号局部转角/`D`推进距离/`N`会话尝试；第四行 `V`滤波实际RPM。台架状态第三行固定T。页面轮换1.2s，单行60ms更新；快过程建议置 `TRACK_DEBUG=1` 用Keil Watch读取 `track_debug`，每100ms更新，无阻塞串口printf。

快照还包含请求RPM、实际RPM、置信度、推进目标、会话时长/累计角/路程、运动模式、停止原因及当前/最大控制间隔。若自行接USART，用主循环空闲发送队列，不在20ms控制函数或ISR内printf。

### A. 架空驱动轮，低速正反闭环

1. 在CarConfig.h临时置 `TRACK_BENCH_TEST=1`；逐次用左/右一轮 `+5、−5、+12、−12、+18、−18 RPM`，另一轮0，重新编译烧录。启动仅测试一次，3s自动停；KEY0/KEY2或运行中KEY1均可立即停。结束全部A测试后恢复 `TRACK_BENCH_TEST=0` 再上地面。
2. **看T/V、正负号和停止R**：非零5RPM目标应持续保留5，正向V为正、反向为负；20ms偶尔0count正常，看100ms窗口平均和是否平稳起转。另一轮应停，3s后STOP R18。P通过Watch观察，因为台架T页固定。
3. **异常含义**：T正而实际轮倒转→核对TB6612方向脚/原Motor宏；轮正转V负→编码器A/B接线/原Encoder宏；T5实际不动、P频繁助推→低速摩擦或负载；只有一个方向冲动→该方向补偿/机械阻力。不能仅凭软件镜像就改符号宏。
4. **下一步**：先排接线/机械问题，再对该轮该方向偏置PWM作0.5%小步调节；观察是否需要提高真实最低稳定转速供TURN/ALIGN配置选用，保留5RPM目标语义，不把它偷偷抬高。换向正常却R2时先看V的惯性持续，再在200～400ms内微调故障宽容；持续相反反馈则修实际接线，不能靠扩大宽容隐藏。

### B. 直线循迹

1. 恢复bench=0，中心探头放线上按KEY1；KEY5是原30%开环检查，不能用来评估循迹。
2. **看IR/E、T/V/P、最大控制间隔**：中心两轮目标相同，IR中心稳定；轻左偏左T低右T高，轻右偏镜像。T按斜坡变化，实际V可有编码器量化，但不应反复高助推、无偏差却长期一轮停。
3. **异常含义/下一步**：IR左右颠倒先核对物理PF顺序；T对而V偏说明A的速度/摩擦未解决；T随±1跳动摆动先小调已有中心死区/位置滤波；实车调度超过40ms会TIME! R3，检查空闲OLED传输耗时/外部阻塞代码，不先修改PID。默认OLED只发8像素字节片、到期前3ms不启动；主机测试不能证明实际I2C耗时。

### C. 单独左直角

1. **看状态H/D、置信度、推进D/goal、A、T/V**：CONF两帧以上；可靠左边形态选D−1；APPR先同步低速、再推进、末段降速；达到计算goal后FAST；A左正，50°SLOW、70°18RPM找线；六帧合格线→ALIGN→EXIT→TRACK。
2. **正常**：不会扫到一帧中心就结束；ALIGN逐渐居中；EXIT T平滑恢复，不在短白缝后立刻大反扫。
3. **异常含义/下一步**：APPR R5看左右V差和偏航，先修A再调同步补偿；轮轴未到顶点用正trim增加推进，过顶点用负trim减少推进，按实测判定，不改175mm几何；FAST A负说明实际方向/反馈错误；70°后越线，先降低FIND_RPM或提前慢转，再看ALIGN参数。R10～13是会话预算，不先扩预算。

### D. 单独右直角

1. 使用同尺寸镜像跑道；**看D+1、A右负、左右T/P正负及阶段时序**。与C有相同门槛和退出保护；有有效右hint的模糊宽角不应默认左。
2. **异常含义**：可靠右角仍D−1，记录IR、置信票和H时效，核对探头位序；D+1却物理左转说明A方向检查未通过；方向正确但只右角起转/接线差，重点看右正转与左反转的负载，不直接改共用PI。
3. **下一步**：对比A测出的对应方向偏置，随后微调FIND_RPM/ALIGN_BASE或ALIGN_KP。保持C/D使用同一状态机和门槛，不新增右转特例。

### E. 连续两个角

1. 分别测试左→左、右→右、左→右、右→左；**看第二角D、H、重新武装与N/会话时长**。
2. **正常**：可靠新角点覆盖旧历史；离开前角后原重新武装条件160ms稳定窄线+50mm前进成立，再识别第二角。两角间若已稳定TRACK600ms+30mm，会话重新从0开始；否则沿用总预算，不能因瞬间居中归零。
3. **异常含义/下一步**：第二角方向沿用前角，先查当前形态置信/IR与hint是否过期；过近第二角未武装，先确认是否达到原50mm条件及传感器175mm前置几何，再考虑实际跑道适配；ALIGN/EXIT反复切搜索，先增接线稳定性或降低慢转/恢复速度，不靠增尝试次数掩盖。

### F. 完整跑道与保护检查

1. **看N、R、状态、T/V/P和控制间隔**，记录最差左右角而非只记成功圈。先低速验证整圈和左右对称，再考虑加基础速度。
2. **正常**：白缝20～100ms保留低速预期修正；真正找不到线按15°→扩大→有限反向搜索；重复假接线不会重获预算。最终恢复稳定TRACK或STOP PWM0，需要人工重启。
3. **异常含义/下一步**：N不断重置但没有稳定600ms+30mm属于逻辑异常，应保存快照；R9为局部搜索耗尽，R10/11/12/13分别总时间/角度/路程/尝试保护；R2编码器故障；R3调度异常。优先回到失败所属A/C/D项解决摩擦、推进或对准，再评估预算。压力模型已有一个右角ALIGN丢线例子，实车需特别复现核对。
